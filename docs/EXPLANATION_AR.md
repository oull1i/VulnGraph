# VulnGraph — شرح المشروع بالعربي

## فكرة المشروع

**VulnGraph** منصة دفاعية ذكية في *طريقة ترتيب العمل* (وليست نموذج ذكاء اصطناعي مدربًا) لتحليل الثغرات المتعلقة بالمكتبات البرمجية والتبعيات. تفيد فرق **Vulnerability Management** و**Application Security (AppSec)** و**Software Supply Chain Security**.

الفكرة: قد يوجد لدى الفريق عشرات الثغرات، ولكن لا يعني حصول ثغرة على CVSS مرتفع أنها أول ما يجب إصلاحه دائمًا. لذلك يضيف النظام مؤشرات وجود استغلال موثّق واحتمالية استغلال متوقعة، بالإضافة إلى سياق أهمية النظام والتعرض للإنترنت، ثم يقدم أسباب النتيجة.

## ما الذي نفذناه بالفعل؟

1. **محلل SBOM:** يستقبل CycloneDX JSON إصدارات 1.4 إلى 1.7، يقرأ المكتبات والإصدارات، ويربط الثغرات بمراجع `bom-ref`.
2. **خريطة الاعتماديات:** تميز المسار المباشر وغير المباشر للمكتبات في المستند، ولا تعتبره إثباتًا لوجود مسار هجوم فعلي.
3. **OSV اختياري:** استعلام عن الثغرات العامة المرتبطة بنسخ المكتبات، ولكن فقط بعد اختيار المستخدم ذلك صراحة. ليس فحص شبكات أو اختراق مواقع.
4. **EPSS وKEV:** إضافة أدلة من FIRST وCISA عند توفرها. الاستعلامات لها حدود، والأخطاء لا تُخفى ولا تتحول إلى أرقام متخيلة.
5. **محرك الأولويات:** معادلة واضحة من 100 نقطة مع أسباب وأوزان كل عامل، لا يدعي أنها احتمال الاستغلال.
6. **واجهة تفاعلية:** إحصاءات، مستويات خطورة، بحث وتصفية، رسم للتبعيات، تفصيل كل ثغرة، والتبديل بين العربية والإنجليزية.
7. **إعدادات السياق:** تغيّرين هل النظام مكشوف للإنترنت، وأهميته من 1 إلى 5؛ تتغير الأولوية تلقائيًا.
8. **تقرير JSON:** يمكن استخدامه لمراجعة الإصلاحات وتوثيق القرارات.
9. **CLI وREST API:** تشغيل آلي دون واجهة، واستخدامه ضمن عمليات CI/CD.
10. **اختبارات وأمان:** حدود أحجام، التحقق من المدخلات، no-store، CSP، عدم تخزين البيانات، Docker بحساب غير root.

## من أين تأتي البيانات؟

- **CycloneDX:** ملف جرد للمكونات والتبعيات، وقد يتضمن ثغرات مذكورة فيه بالفعل.
- **OSV:** قاعدة ثغرات عامة تعيد معلومات حقيقية عن مكتبات لها Package URL وإصدار معروف.
- **CVSS:** شدة الثغرة إذا توفرت بياناتها؛ لا نعطي قيمة افتراضية إن غابت.
- **FIRST EPSS:** تقدير احتمالية استغلال CVE خلال الثلاثين يومًا القادمة، وهو مؤشر منفصل عن شدة CVSS.
- **CISA KEV:** قائمة الثغرات التي توجد عليها أدلة استغلال معروف. غياب الثغرة من القائمة لا يعني أنها غير قابلة للاستغلال.

## كيف تُحسب الأولوية؟

`Risk score = CVSS × 3.5 + EPSS × 25 + KEV(25/0) + exposure(10/0) + (criticality − 1) × 1.25`

- **80–100:** حرجة
- **60–79.9:** عالية
- **35–59.9:** متوسطة
- **0–34.9:** منخفضة

هذه سياسة فرز أولويات قابلة للتعديل، وليست مقياسًا صناعيًا معتمدًا أو احتمالًا. لا يمكن الاستنتاج أن مكتبة تُستخدم وقت التشغيل لمجرد ظهورها في SBOM.

## تجربة بدون خبرة تقنية أو برامج إضافية

لديك مشروع Python يحتاج إلى تشغيل خادم (وليس صفحة HTML مستقلة). يمكن نشر ملفات المشروع على GitHub، لكنه لن يصبح تطبيق ويب عام حتى تستضيفي الـBackend. للاختبار محليًا، تحتاجين Python 3.11 أو أحدث، ويمكن تنفيذ الأوامر من PowerShell دون VS Code.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m vulngraph.cli serve
```

بعدها افتحي `http://127.0.0.1:8000`، واختاري **Load demo**. العينات المعروضة **خيالية** وتخص السيناريو التعليمي فقط. لتحليل مشروع واقعي استخدمي ملف SBOM فعليًا، لا صورًا من موقع أو بيانات عمل حساسة بدون تصريح.

## السيناريو في المقابلات

**س: ما المشكلة التي يحلها مشروعك؟**

> يساعد فرق أمن التطبيقات على فرز الثغرات المرتبطة بالمكتبات بحسب الأدلة المتاحة والأهمية التشغيلية للنظام، بدل ترتيبها وفق CVSS وحده. ويتيح مراجعة العوامل التي أثرت في كل قرار.

**س: لماذا استخدمتِ OSV وEPSS وKEV معًا؟**

> لأن كل مصدر يقيس شيئًا مختلفًا: بيانات الثغرة في المكتبة، واحتمالية الاستغلال في العالم الحقيقي خلال 30 يومًا، والأدلة المعروفة على الاستغلال. جمعها مع سياق بيئة العمل ينتج قائمة عمل أكثر قابلية للنقاش.

**س: هل هذا ذكاء اصطناعي؟**

> ليس نموذجًا تعلميًا؛ إنه محرك تحليلي استدلالي قابل للتفسير. يمكن إضافة نماذج لاحقًا إذا توفرت بيانات معنونة وأمكن اختبار دقتها بشكل مستقل.

**س: هل تنفذين استغلالًا للثغرات؟**

> لا. المشروع لا يفحص خوادم العملاء أو يشغّل exploits. هو أداة جرد وفهم وترتيب أولويات التحديثات.

**س: ماذا إذا لم يعُد OSV بأي ثغرة؟**

> لا أعني أن المكتبة آمنة. قد تكون البيانات ناقصة أو حزمة غير مدعومة، لذلك أعرض القيود ولا أدّعي تغطية كاملة.

**س: ما المخاطر المتبقية في المنتج؟**

> لا توجد مصادقة مناسبة لاستضافة عامة متعددة المستخدمين، ولا دليل على الوصول وقت التشغيل، والتقييم heuristic وغير معاير ببيانات تاريخية. هذه تطويرات مقترحة وليست ميزات موجودة حاليًا.

## صيغة قوية للسيرة الذاتية

**VulnGraph — Explainable Vulnerability Triage Platform**

Developed a bilingual software supply-chain vulnerability triage platform using Python, FastAPI, CycloneDX SBOM parsing, opt-in OSV integration, and contextual CVSS/EPSS/KEV prioritization. Implemented interactive dependency visualization, interpretable remediation scoring, REST APIs, CLI automation, secure input handling, and automated tests with Docker-ready deployment.

لا تكتبي أي أرقام عن دقة الكشف أو عدد الثغرات المكتشفة في العالم الحقيقي دون نتائج تجريبية حقيقية موثقة.
